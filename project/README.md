# 工具盒盘点工作台

黄色便携式工具盒的视觉盘点演示项目，展示工具照片、数量核对、缺失项定位及检测标注。

> 当前是 **Mock 演示版**，不是已经接入真实视觉模型的盘点产品。样例结果来自预设数据；用户上传的照片仅在浏览器中预览，不会生成真实识别结果。运行演示无需 API Key。

## 1. 环境要求

- 建议使用 Node.js 22 LTS 和随附的 npm（Docker 配置也使用 Node.js 22）。
- 首次安装依赖需要联网。
- Windows 用户可使用根目录的 `start-demo.cmd`。
- 使用 Docker 启动时，需要安装并启动 Docker Engine / Docker Desktop。

## 2. Windows 一键启动

双击项目根目录中的 `start-demo.cmd`，或在命令提示符中运行：

```bat
cd /d E:\toolbox-vision-demo
start-demo.cmd
```

脚本会检查 Node.js，在缺少 `node_modules` 时安装依赖，在缺少 standalone 服务时构建，然后启动服务。

看到服务就绪后，访问：

**http://127.0.0.1:3002**

在启动终端按 `Ctrl+C` 停止服务；也可以关闭该终端。

**注意：脚本不会自动重新构建已有产物。** 修改或更新源码后，请先停止旧服务，再运行：

```bat
npm ci
npm run build
start-demo.cmd
```

Windows 下重新构建前应关闭本项目的旧服务，避免 `sharp` DLL 被占用。依赖没有变化时，可以省略 `npm ci`。

## 3. 开发模式

在项目根目录执行：

```sh
npm ci
npm run dev -- --port 3002
```

访问 **http://127.0.0.1:3002**。开发模式支持修改后自动更新，适合日常开发。

`npm run dev` 已绑定 `127.0.0.1`；若不指定 `--port`，默认使用 3000 端口（端口占用时以终端实际输出为准）。

## 4. 构建及生产模式启动

先安装依赖并构建：

```sh
npm ci
npm run build
```

构建采用 Next.js standalone 输出，之后会执行 `scripts/prepare-standalone.mjs`，复制静态资源；在 Windows 上还会复制对应的 `sharp` 解码库。

### Windows 命令提示符（CMD）

```bat
set HOSTNAME=127.0.0.1
set PORT=3002
npm start
```

### Windows PowerShell

```powershell
$env:HOSTNAME = "127.0.0.1"
$env:PORT = "3002"
npm start
```

### macOS / Linux

```sh
HOSTNAME=127.0.0.1 PORT=3002 npm start
```

以上命令均访问 **http://127.0.0.1:3002**。不要直接将浏览器打开到磁盘中的 `public/inspection.html`，样例盘点需要同源后端 API。

`npm start` 只启动已有构建，不会自动构建。源码修改后需要停止服务、重新执行 `npm run build`，再启动。

## 5. 启动检查与测试

启动服务后，可以访问以下地址确认服务状态：

- `/`：跳转到 `/inspection.html`。
- `/inspection.html`：盘点工作台。
- `/api/health`：预期包含 `ok: true`、`mode: "mock"`、`qwenConfigured: false`。
- `/api/inventory`：返回暂定工具清单。

保持服务运行，在另一个终端执行：

```sh
npm run typecheck
npm test
```

测试默认连接 `http://127.0.0.1:3002`，不会自动启动服务。如果服务运行在其他地址，可设置 `TEST_BASE_URL`，例如 PowerShell：

```powershell
$env:TEST_BASE_URL = "http://127.0.0.1:3000"
npm test
```

现有 API 测试覆盖健康检查、工具清单、四组样例图片与盘点结果，以及缺图、伪造图片、扩展名不匹配、超限上传和缺少 `sampleId` 的请求。接口测试通过不等同于真实识别能力验收或完整浏览器交互验收。

## 6. Docker 启动

在项目根目录执行：

```sh
docker compose up --build -d
docker compose logs -f web
```

访问 **http://127.0.0.1:3000**。

停止并移除容器：

```sh
docker compose down
```

容器使用非 root 用户，宿主机端口仅绑定本地回环地址。Compose 配置包含 `/api/health` 健康检查。

**验收状态：Docker 配置已准备，但容器构建及 Engine 实际运行仍待验证，不能视为已验收通过。**

## 8. 当前功能与边界

- 前台提供四组内置记录：完整、缺少套筒、缺少大号手柄、缺少小号手柄。这些是演示数据，并非数据库中保存的真实历史记录。
- 样例照片经 `/api/analyze` 校验后，根据 `sampleId` 返回预设结果，不是根据图像内容推理。
- 页面中的缺失说明和检测框也有前端预设数据；目前并非完全由 API 返回结果驱动。
- 支持显示或隐藏图像标注，展示清单、数量差异及缺失位置。
- 自定义上传仅做浏览器预览；点击运行盘点会提示真实模型未接入，不会调用真实视觉识别。
- 后端支持 JPG / PNG / WEBP 校验，包括文件扩展名、MIME、文件签名、解码检查；文件大小上限为 7 MiB，并设置了解码像素限制。
- 标准清单六类工具的配置合计为 53 件，但属于暂定基线，特别是批头数量仍需人工核验。
- 尚未实现真实 Qwen Provider。`.env.example` 仅为后续配置模板，填写密钥或修改 `ANALYSIS_MODE` 不会自动开启真实识别；当前上传限制也在代码中写死，不能假定模板中的变量已经生效。

不要将密钥放入前端、发到聊天或提交到源码仓库。开发代理所使用的模型服务与网页视觉识别接口是两套独立配置。

## 9. 从当前 Demo 到完整交付：待办清单

当前版本具备演示界面、图片输入校验和 Mock API，但尚不具备真实识别、可靠盘点或生产运维能力。以下是产品交付前的工作范围，不代表这些功能已经实现。具体方案须在数据、准确率目标和部署环境确定后再定。

### P0：真实盘点的必要工作

1. **核定工具标准与判定规则**
   - 由业务方逐项确认工具类别、名称、标准数量、套件计数方式及允许缺省规则，优先复核当前标注为暂定的套筒、批头和延长杆数量。
   - 为不同工具盒型号维护独立且带版本号的清单；定义新旧清单变更后历史结果如何解释。
   - 确认遮挡、工具未归位、替代工具、多余工具、照片不完整等情况的处置规则。

2. **确定并验证视觉方案**
   - 收集有代表性的真实照片：不同设备型号、拍摄角度、距离、光照、背景、磨损、遮挡及空槽位；标注物品类别、数量、位置和复核标签，并隔离独立验证集。
   - 评估 Qwen-VL 等视觉语言模型能否稳定识别本项目所需的细粒度工具和数量，尤其是相似零件与密集批头。不能仅凭模型可调用就认为适合盘点。
   - 比较至少一种备选方案：提示词驱动的视觉模型、专用目标检测/分割模型，或“视觉模型初识别 + 规则/人工复核”的组合。对固定工具盒，可评估先定位托盘槽位，再逐槽识别和计数，避免直接对整张照片做自由描述。
   - 用验证集报告按类别的精确率、召回率、漏检率、误报率、计数准确率、缺失定位准确率、人工复核率、延迟和单次成本。由业务方确定上线门槛；未达到门槛的类别应返回“无法判断/需复核”，不得伪造确定结论。

3. **实现服务端 Qwen Provider 和分析流程**
   - 确认实际服务供应商、API Base URL、认证方式、模型 ID、图片输入协议、响应格式、区域/坐标定义、超时、限流及数据保留政策。当前 `.env.example` 是模板，正确端点和协议尚未确认。
   - 在服务端实现模型客户端、配置校验、超时/重试策略、结构化输出解析和 schema 校验。将模型原始响应映射为统一的盘点结果结构；模型输出无法解析或字段不合法时返回明确错误或复核状态。
   - 从 `/api/analyze` 移除“必须传 `sampleId` 才可返回盘点结果”的 Mock 约束；由明确的分析模式或独立接口区分 Mock 与真实分析。不得让任意上传图片通过 sampleId 直接继承与图像无关的样例结论。
   - 定义各类工具的检测框/缺失槽位坐标系、归一化方式、图片缩放与裁切坐标还原规则；增加边界、越界、重复框和低置信度处理。当前 Mock 框为演示坐标，不是模型验证过的定位结果。
   - 实现失败、拒答、图片不适合识别、部分识别和人工复核等状态。不得把模型的自然语言推测当作已确认的计数。

4. **让页面使用真实 API 返回值**
   - 上传后由服务端分析并返回检测结果、清单差异、置信度、复核状态和警告；前端标注、结论和数量都以同一份 API 响应渲染。
   - 清除前端对预设场景的硬编码结果依赖，或将其明确保留为仅供 Demo 的独立模式。修复当前页面与配置数据重复导致的结果不一致风险。
   - 为加载中、超时、服务不可用、重试、分析失败、低置信度、需人工复核和无缺失等状态提供完整交互；上传新图或切换样例时取消/忽略过期请求。
   - 显示模型/清单版本、分析时间、数据来源及“AI 估计/人工确认”状态。提供人工修正识别类别与数量的入口，并保留修正前后值。

### P1：可运营、可维护的交付

- **记录与追溯**：确认是否需要用户、设备或工具盒型号、盘点记录、图片、模型版本、清单版本、识别结果及人工修订的持久化。若需要，设计数据库、备份、保留期限和删除机制；当前项目没有数据库，前台“历史记录”只是内置样例。
- **安全与隐私**：明确图片是否发送给第三方模型、数据地域和保留政策；限制上传体积、像素、请求频率及并发；保护 API Key（仅服务端环境变量或密钥管理服务），避免日志记录密钥和不必要的图片内容；配置鉴权、访问控制、CORS/CSRF 策略、错误脱敏及审计日志。公开部署前必须评估认证和滥用防护。
- **服务韧性**：设置连接/读取超时、有限重试、并发队列、速率限制、供应商错误映射、健康检查、请求 ID 和可观测指标；明确模型 API 不可用时的降级策略。不要对非幂等请求盲目重试。
- **测试**：增加真实 Provider 的协议契约测试（使用 mock server，不依赖真实密钥）、上传和响应 schema 单元测试、前端主要流程浏览器测试、错误/超时/并发测试，以及经授权的真实图片回归集。保护含敏感信息的测试图片和基准结果。
- **部署**：确认目标环境和域名，配置 HTTPS、服务端密钥、网络出口、资源限制、健康检查、日志、监控、备份和回滚流程；在目标 Windows 或 Linux/Docker 环境实际构建并验收。当前 Docker 文件只声明 Mock 模式，且 README 所述 Docker 构建仍待实际验证。
- **产品准备**：核定支持的工具盒型号、使用说明、错误处理流程、支持责任人、模型和清单更新流程、已知限制及用户隐私告知。

### P2：可选的产品化能力

- 多工具盒型号/模板选择、用户/组织与权限管理、可检索的历史盘点、导出报告、批量盘点和审计报表。
- 如需离线或低延迟运行，评估本地部署模型及设备算力、模型更新和边缘设备维护成本。
- 依照业务量评估图片对象存储、后台任务队列、模型路由与多供应商切换；低流量单机 Demo 不应未经需求确认就引入这些基础设施。

### 建议实施顺序

1. 业务方先确认清单、场景、错误成本、隐私约束和可接受的准确率/复核比例。
2. 准备并标注真实数据集，做 Qwen 与备选识别方案的离线对比；确认坐标输出和目标服务商 API 文档。
3. 实现服务端 Provider 与统一结果 schema，在小范围测试环境验证图片上传、识别、错误处理和人工复核闭环。
4. 达到书面验收门槛后，再完成页面联调、持久化/权限（如有需求）、安全检查、部署及回滚演练。
5. 由业务方用独立真实验收集签字确认。Mock API 测试通过不能替代这一步。

### 交付验收门槛

正式交付前至少应逐项记录“通过/不通过/不适用”及证据：

- [ ] 业务确认工具清单、计数口径、支持型号和版本策略。
- [ ] 已选定识别方案；有独立真实图片验收集和按类别的准确率、计数及定位指标，达到业务约定门槛。
- [ ] 后端真实 Provider 使用经确认的端点/模型；密钥仅在服务端；无密钥、超时、限流、拒答和异常响应均有可预测处理。
- [ ] 任意符合约束的上传照片走真实分析流程；页面结果由 API 响应驱动；Mock 场景不会冒充真实识别结果。
- [ ] 低置信度、遮挡、不支持场景能够要求人工复核；人工修正不会丢失原始识别信息（若业务要求记录）。
- [ ] 关键 API、浏览器流程、上传边界和模型错误路径测试通过；构建无误。
- [ ] 在目标部署环境完成启动、健康检查、HTTPS/访问控制（适用时）、日志与告警检查、升级和回滚演练。
- [ ] 数据授权、第三方模型传输告知、图片保留/删除及运维责任人已确认。

在业务验收指标、真实识别能力及目标环境部署尚未验证前，不应对外承诺“自动准确盘点”或将当前 Demo 作为生产系统交付。

## 10. 常见启动问题

- **提示找不到 Node.js / npm**：安装 Node.js 22 LTS 后，重新打开终端。
- **端口被占用**：停止之前启动的项目实例，或更换端口；测试时同步设置 `TEST_BASE_URL`。
- **提示缺少 `.next/standalone/server.js`**：先运行 `npm ci` 和 `npm run build`。
- **修改代码后页面没有变化**：生产模式不会自动更新，停止旧服务后重新构建并启动；日常开发建议使用开发模式。
- **Windows 构建报 DLL 占用或权限错误**：先停止本项目旧服务，再重新构建。
- **图片或样例接口加载失败**：确认通过 HTTP 地址访问，并确认执行了完整的 `npm run build`，而非跳过资源复制步骤仅执行 `next build`。
- **上传后没有识别结果**：这是当前演示版的功能边界，不是填写 API Key 就能解决的问题。
